Start with the [React quickstart](/docs/quickstarts/tanstack-start/react).
Use Cloudflare's [Start deployment setup](https://developers.cloudflare.com/workers/framework-guides/web-apps/tanstack-start/)
for the Vite plugin, Worker configuration and bindings. WordPress can run on any host.

## Register the integrations

```ts title="src/lib/kizlo/server/index.ts"
import { createKizlo } from "kizlo"
import { cloudflare } from "kizlo/tanstack-start/cloudflare"
import { tanstackStart } from "kizlo/tanstack-start/react/server"
import { introspection } from "./generated"

export const { client, handler } = createKizlo({
  integrations: [tanstackStart(), cloudflare()],
  introspection,
})
```

`tanstackStart()` maps `VITE_KIZLO_BASE_URL` and WordPress environment variables, and uses Start's
native request context and cookie helpers. `cloudflare()` adds trusted Cloudflare connection metadata.
Neither installs an application data cache or requires a second async-storage scope.

## Forward Worker bindings

```ts title="src/server.ts"
import app from "@tanstack/react-start/server-entry"
import { withCloudflare } from "kizlo/tanstack-start/cloudflare"

export default withCloudflare(app)
```

The bridge passes native bindings and execution context to React Start, defaults responses without a cache
policy to `Cache-Control: no-store`, and encodes authored resource tags. It does not create hosting resources.

Register the context alongside your existing router registration, using generated Cloudflare types:

```ts title="src/router.tsx (type registration)"
declare module "@tanstack/react-router" {
  interface Register {
    server: { requestContext: { env: Env; executionCtx: ExecutionContext } }
  }
}
```

To expose bindings to Kizlo procedures, augment `ProcedureContext`:

```ts title="src/kizlo-env.d.ts"
import "kizlo"

declare module "kizlo" {
  interface ProcedureContext {
    env: Env
    executionCtx: ExecutionContext
  }
}
```

Direct server calls read the active Start request. Outside a Start request, no ambient request values
are supplied. Core HTTP handlers accept explicit platform values and work without async storage;
custom runtimes can supply a `requestContext` adapter through `createIntegration()`.

## Mount the API

```ts title="src/routes/api.kizlo.$.ts"
import { createFileRoute } from "@tanstack/react-router"
import { createApiHandlers } from "kizlo/tanstack-start/server"
import { handler } from "@/lib/kizlo/server"

export const Route = createFileRoute("/api/kizlo/$")({
  server: { handlers: createApiHandlers(handler) },
})
```

Kizlo's API responses use `Cache-Control: private, no-store`. Framework route parameters are not
platform context. Authorize private resources inside their server handlers.

## Opt pages into CDN caching

Enable native Workers Cache with `cache: { enabled: true }` in your Worker configuration.
Responses stay uncached until you supply an explicit cache policy. Set it through Start's native
route `headers` callback; loader data is available there for tag generation:

```ts title="src/routes/product.$slug.tsx"
import { createFileRoute } from "@tanstack/react-router"
import { createCdnHeaders } from "kizlo/tanstack-start/cloudflare"

export const Route = createFileRoute("/product/$slug")({
  loader: ({ params }) => ({ productId: params.slug }),
  headers: ({ loaderData }) => {
    if (!loaderData) return { "Cache-Control": "no-store" }
    return createCdnHeaders({
      maxAge: "1 hour",
      staleWhileRevalidate: "5 minutes",
      tags: [`product:${loaderData.productId}`],
    })
  },
})
```

Replace the example loader with your product lookup and derive tags from its result.
Durations accept seconds as numbers or strings such as `"1 hour"`; `staleIfError` defaults to zero.
The browser revalidates while Cloudflare uses the edge policy.

## Cache response variants

Add `vary` when a request header changes the public response, such as language selection:

```ts
createCdnHeaders({
  maxAge: "1 hour",
  vary: ["Accept-Language"],
})
```

Cloudflare stores a separate variant for each header value. No `Vary` is added by default;
preserve framework-required values when composing headers. Keep private cart and account responses
uncached instead of varying public responses by session cookies.

## Own the response policy

Kizlo preserves your explicit policy and `Vary` fields, including cacheable policies supplied to
cart or account routes by a layout or middleware. It does not veto caching based on cookies,
authorization, response status or render errors. Cookie handling, credential variance and failure
policies are application choices. Cloudflare's own cache eligibility rules still apply.

<Callout>
  Shared caching reuses the entire response, including serialized provider state. Keep user-specific
  UI client-side on those pages, and choose their headers accordingly. There is no cache-policy middleware.
</Callout>

## Select where Clerk middleware runs

Clerk's Start provider serializes middleware-provided auth state into HTML. Use `matchMiddleware()`
to make the server authentication boundary explicit, while keeping Clerk's browser provider on public pages:

```ts title="src/start.ts"
import { clerkMiddleware } from "@clerk/tanstack-react-start/server"
import { createCsrfMiddleware, createStart } from "@tanstack/react-start"
import { matchMiddleware } from "kizlo/tanstack-start/react/server"

export const startInstance = createStart(() => ({
  requestMiddleware: [
    createCsrfMiddleware({ filter: (ctx) => ctx.handlerType === "serverFn" }),
    matchMiddleware(clerkMiddleware(), [
      "/account(.*)",
      "/checkout(.*)",
      "/orders(.*)",
      "/sign-in(.*)",
      "/sign-up(.*)",
      "/api/(.*)",
      "/_serverFn/(.*)",
      "/__clerk/(.*)",
    ]),
  ],
}))
```

- **Patterns:** pass a string or array of [path-to-regexp patterns](https://nextjs.org/docs/app/api-reference/file-conventions/proxy#matcher), such as `/privacy`, `/orders(.*)` or `/account/:path*`. Matching is case-insensitive, accepts a trailing slash and ignores query strings.
- **Advanced matching:** use negative lookaheads for exclusions, or a synchronous `(request) => boolean` callback for header and query checks. Native ordering and dependencies are preserved.
- **Server functions:** include their base path when they use Clerk's `auth()` helper; `/_serverFn` is Start's default. Private resources must still check authentication and ownership independently.

Selecting middleware does not set cache policy.

## Authenticate without Clerk middleware

With middleware, use Clerk's Start `auth()` helper. Without middleware, that helper throws:
authenticate through [`clerkClient().authenticateRequest(request)`](https://clerk.com/docs/reference/backend/authenticate-request),
handle handshake headers or redirects, then authorize using `.toAuth()`. Fetch a full user only after
verifying identity with `clerkClient().users.getUser(userId)`.

## Revalidate public responses

Call these helpers from an independently authorized server route, webhook or server function:

```ts
import { revalidateTag, revalidateUrl } from "kizlo/tanstack-start/cloudflare"

await revalidateTag("catalog")
await revalidateUrl("/collections")
await revalidateUrl(new URL("https://shop.example/product/shirt?size=m"))
```

The active Start execution context must provide native `cache.invalidate()`.
Both helpers mark matching responses stale; the next request refreshes them under their stored
stale-while-revalidate policy. They do not regenerate pages immediately. Missing support and provider failures throw.

URLs accept an absolute pathname or a same-origin HTTP(S) URL; queries and fragments are ignored.
`revalidateUrl()` uses Cloudflare's native path-prefix selector: `/collections` also selects
`/collections/featured` and `/collections-sale`, while `/` selects every path in the current Worker entrypoint.
No automatic page tags are needed. Cross-origin URLs and embedded credentials are rejected; explicit resource tags remain scoped to the request host.

For global changes, call `purgeCache()` from the same export. It requires native `cache.purge()`
and removes every cached response in the Worker entrypoint, across its hosts. The next request is a
cold miss. Authorize this operation independently; provider failures throw.

## Revalidate on WordPress changes

Update Kizlo core before the WooCommerce extension, then deploy both event-producing plugin updates before enabling `revalidator()`. The WooCommerce extension refuses to start against core versions missing the dependency APIs.
It uses the existing signed `/webhooks` route and never makes a response cacheable:

```ts title="src/lib/kizlo/server/revalidation.ts"
import { revalidator } from "kizlo/tanstack-start/cloudflare"

export const tags = {
  product: (id: number) => `product:${id}`,
  category: (id: number) => `category:${id}`,
}

export const contentRevalidation = revalidator({
  postTypes: {
    product: {
      resourceTag: tags.product,
      collectionTags: ({ affected_terms }) =>
        (affected_terms.product_cat ?? []).map(tags.category),
    },
  },
  taxonomies: { product_cat: { resourceTag: tags.category } },
  settings: "purge",
})
```

Put `contentRevalidation` alongside `tanstackStart()` and `cloudflare()` in `integrations`.
Mount the webhook on the configured public origin and the **same cache-owning Worker entrypoint**
as the cached pages. Origin mismatch fails; matching origins alone cannot prove entrypoint ownership.
`settings: "purge"` handles every supported settings event with a full Worker cache purge. Use this
boundary for URL structures, branding and other global configuration instead of calculating affected content.
Existing per-event settings callbacks remain available when you deliberately want selected tags.

### Choose dependencies for each response

Reuse your tag functions in `createCdnHeaders`. Build tags from existing taxonomy fields and term IDs.
For a WooCommerce product, use `product.categories`, `product.tags`, `product.brands` and global
attribute terms. Managed WordPress post-type responses retain their taxonomy ID arrays.

```ts
createCdnHeaders({
  maxAge: "1 hour",
  tags: [tags.product(product.id), ...product.categories.map(({ id }) => tags.category(id))],
})
```

Put the product's own tag first. Term-change events include affected descendants, so changing a
parent URL reaches responses tagged with child terms without changing product assignments. Add other
resource tags when the response separately loads their data.

- **Product detail:** tag its product ID and the assigned terms it renders. Product-local attribute options are not shared terms.
- **Category listing:** tag its category ID even when empty. Pagination, search, filters, sort and counts declare their collection scope independently of the returned product IDs and retain distinct cache keys.
- **Shared category tags:** moving a product from A to B invalidates its product tag and configured A/B scopes. Renaming a category reaches every response carrying that category tag without enumerating products. Use a separate `category-products:id` tag only when you want narrower collection invalidation.
- **Custom content:** configure actual post-type/taxonomy slugs with the same callbacks. For example, a dedicated `policy` post type can invalidate `policy:id` without invalidating unrelated policies.

### Understand supported change signals

| Change | Signal and capture boundary |
| --- | --- |
| Publish or published edit | `post.created` / `post.updated`, `wp_after_insert_post`, finalized after late REST enrichment |
| Unpublish, trash or delete | `transition_post_status`, `trashed_post`, `before_delete_post` / `deleted_post` with retained identity |
| Assign or remove terms | `set_object_terms`, `delete_term_relationships` / `deleted_term_relationships` with previous/current ancestry |
| Rename, reparent or delete a term | `edit_terms` / `saved_term`, `pre_delete_term` / `delete_term`, with previous/current subtree and ancestry; `edit_term_taxonomies` / `edited_term_taxonomies` also capture children reparented by deletion |
| Exposed metadata, Kizlo custom fields and SEO | `added_*_meta`, `updated_*_meta`, `deleted_*_meta`, filtered to exposed fields |
| Product/variation writes | `woocommerce_after_{product,product_variation}_object_save`, before/after delete and variation trash hooks |
| Global attribute definitions | `woocommerce_attribute_added`, `woocommerce_attribute_updated`, `woocommerce_attribute_deleted`; indexed settings event with old/new `pa_*` keys |

No dedicated stock listener or stock-only suppression is installed. Ordinary watched content events
still run; use TTL or a separate request for stock-only writes, including stock-dependent counts and
filters. Direct SQL, arbitrary plugin tables and writes bypassing these hooks need their own event integration.
Variation reparenting invalidates both parent resources; WooCommerce remains responsible for synchronizing
its own product children and lookup data before a fresh response reads them.

Configured post/term rules require a complete `affected_terms` map. Missing or unknown dependency
history returns 422; unconfigured types remain ignored. The map is an affected union, not the current
assignments or a before/after snapshot. Invalid callback outputs fail before provider calls; invalidation
submits every selected tag in sequential batches of at most 100 and fails acknowledgement on rejection.

### Keep dependency headers within the budget

Response tags retain caller order after deduplication. The wrapper keeps the longest whole-tag prefix
within 1,000 tags and 16,384 encoded bytes, including commas. The unchanged host-scoped SHA-256 format
(`kizlo:t:` plus 64 hexadecimal characters) fits **224** unique tags. Overflow logs
`KIZLO_CDN_TAGS_TRIMMED` with the pathname, counts and budgets; malformed individual tags still error.

<Callout>
  Trimming preserves your exact cache policy. A change targeting only a dropped dependency can remain
  stale until the normal refresh policy or another retained tag refreshes it. Put essential dependencies
  first. Event maps and invalidation batches are never trimmed to this response budget.
</Callout>

### Operate delivery and check freshness

See [webhook delivery and recovery](/docs/php/functions/emit-event#delivery-and-recovery) for retries,
native delivery records, manual replay and WP-Cron setup. A successful acknowledgement means every required
handler and provider batch accepted its work. It does not prove that a cached response existed or that
all locations immediately show fresh content. Custom handlers may run again and must be idempotent.

Native invalidation marks responses stale under their stored TTL/SWR/stale-on-error policy. A render
or cache fill already in flight can cross invalidation; no generation fence or atomic worldwide replacement
is provided. Check that race and host/entrypoint isolation on your deployed preview, including Start's
actual cached representations. Local provider mocks do not establish native behavior.

## Migrate and verify

Move React runtime imports to `kizlo/tanstack-start/react/server` and Cloudflare imports to
`kizlo/tanstack-start/cloudflare`. Shared browser, metadata and structural route helpers remain
on `kizlo/tanstack-start` and `kizlo/tanstack-start/server`; these entries do not require React.
Replace the removed `kizlo/tanstack-start/react/cloudflare` import with `kizlo/tanstack-start/cloudflare`; no alias is provided. The shared provider has no runtime React dependency.
Remove Vinext configuration and compatibility patches. Keep existing stored resources until their
retirement is authorized. Use `geoCloudflare()` only behind trusted ingress that prevents forged
`CF-Connecting-IP` headers; it validates syntax, not the sender.

Verify public MISS/HIT behavior on an isolated deployment, then test tag invalidation, private guards
and signed-in versus signed-out public HTML. A local build or dry-run does not prove edge caching,
account permissions or live Clerk behavior. No R2, Durable Objects or Worker response-cache implementation is installed.
