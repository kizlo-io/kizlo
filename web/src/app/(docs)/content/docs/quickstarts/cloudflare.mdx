Start with the [React quickstart](/docs/quickstarts/tanstack-start/react).
Use Cloudflare's [Start deployment setup](https://developers.cloudflare.com/workers/framework-guides/web-apps/tanstack-start/)
for the Vite plugin, Worker configuration and bindings. WordPress can run on any host.

## Register the integrations

```ts title="src/lib/kizlo/server/index.ts"
import { createKizlo } from "kizlo"
import { cloudflare } from "kizlo/tanstack-start/cloudflare"
import { tanstackStart } from "kizlo/tanstack-start/server"
import { introspection } from "./generated"

export const { client, handler } = createKizlo({
  integrations: [tanstackStart(), cloudflare()],
  introspection,
})
```

`tanstackStart()` maps `VITE_KIZLO_BASE_URL` and WordPress environment variables, and uses Start's
native request context and cookie helpers. `cloudflare()` adds trusted Cloudflare connection metadata.
Neither installs an application data cache or requires a second async-storage scope.

## Forward Worker bindings

```ts title="src/server.ts"
import app from "@tanstack/react-start/server-entry"
import { withCloudflare } from "kizlo/tanstack-start/cloudflare"

export default withCloudflare(app)
```

The bridge passes native bindings and execution context to Start, defaults responses without a cache
policy to `Cache-Control: no-store`, and encodes cache tags. It does not create hosting resources.

Register the context alongside your existing router registration, using generated Cloudflare types:

```ts title="src/router.tsx (type registration)"
declare module "@tanstack/react-router" {
  interface Register {
    server: { requestContext: { env: Env; executionCtx: ExecutionContext } }
  }
}
```

To expose bindings to Kizlo procedures, augment `ProcedureContext`:

```ts title="src/kizlo-env.d.ts"
import "kizlo"

declare module "kizlo" {
  interface ProcedureContext {
    env: Env
    executionCtx: ExecutionContext
  }
}
```

Direct server calls read the active Start request. Outside a Start request, no ambient request values
are supplied. Core HTTP handlers accept explicit platform values and work without async storage;
custom runtimes can supply a `requestContext` adapter through `createIntegration()`.

## Mount the API

```ts title="src/routes/api.kizlo.$.ts"
import { createFileRoute } from "@tanstack/react-router"
import { createApiHandlers } from "kizlo/tanstack-start/server"
import { handler } from "@/lib/kizlo/server"

export const Route = createFileRoute("/api/kizlo/$")({
  server: { handlers: createApiHandlers(handler) },
})
```

Kizlo's API responses use `Cache-Control: private, no-store`. Framework route parameters are not
platform context. Authorize private resources inside their server handlers.

## Opt pages into CDN caching

Enable native Workers Cache with `cache: { enabled: true }` in your Worker configuration.
Responses stay uncached until you supply an explicit cache policy. Set it through Start's native
route `headers` callback; loader data is available there for tag generation:

```ts title="src/routes/product.$slug.tsx"
import { createFileRoute } from "@tanstack/react-router"
import { createCdnHeaders } from "kizlo/tanstack-start/cloudflare"

export const Route = createFileRoute("/product/$slug")({
  loader: ({ params }) => ({ productId: params.slug }),
  headers: ({ loaderData }) => {
    if (!loaderData) return { "Cache-Control": "no-store" }
    return createCdnHeaders({
      maxAge: "1 hour",
      staleWhileRevalidate: "5 minutes",
      tags: [`product:${loaderData.productId}`],
    })
  },
})
```

Replace the example loader with your product lookup and derive tags from its result.
Durations accept seconds as numbers or strings such as `"1 hour"`; `staleIfError` defaults to zero.
The browser revalidates while Cloudflare uses the edge policy.

## Cache response variants

Add `vary` when a request header changes the public response, such as language selection:

```ts
createCdnHeaders({
  maxAge: "1 hour",
  vary: ["Accept-Language"],
})
```

Cloudflare stores a separate variant for each header value. No `Vary` is added by default;
preserve framework-required values when composing headers. Keep private cart and account responses
uncached instead of varying public responses by session cookies.

## Own the response policy

Kizlo preserves your explicit policy and `Vary` fields, including cacheable policies supplied to
cart or account routes by a layout or middleware. It does not veto caching based on cookies,
authorization, response status or render errors. Cookie handling, credential variance and failure
policies are application choices. Cloudflare's own cache eligibility rules still apply.

<Callout>
  Shared caching reuses the entire response, including serialized provider state. Keep user-specific
  UI client-side on those pages, and choose their headers accordingly. There is no cache-policy middleware.
</Callout>

## Select where Clerk middleware runs

Clerk's Start provider serializes middleware-provided auth state into HTML. Use `matchMiddleware()`
to make the server authentication boundary explicit, while keeping Clerk's browser provider on public pages:

```ts title="src/start.ts"
import { clerkMiddleware } from "@clerk/tanstack-react-start/server"
import { createCsrfMiddleware, createStart } from "@tanstack/react-start"
import { matchMiddleware } from "kizlo/tanstack-start/server"

export const startInstance = createStart(() => ({
  requestMiddleware: [
    createCsrfMiddleware({ filter: (ctx) => ctx.handlerType === "serverFn" }),
    matchMiddleware(clerkMiddleware(), [
      "/account(.*)",
      "/checkout(.*)",
      "/orders(.*)",
      "/sign-in(.*)",
      "/sign-up(.*)",
      "/api/(.*)",
      "/_serverFn/(.*)",
      "/__clerk/(.*)",
    ]),
  ],
}))
```

- **Patterns:** pass a string or array of [path-to-regexp patterns](https://nextjs.org/docs/app/api-reference/file-conventions/proxy#matcher), such as `/privacy`, `/orders(.*)` or `/account/:path*`. Matching is case-insensitive, accepts a trailing slash and ignores query strings.
- **Advanced matching:** use negative lookaheads for exclusions, or a synchronous `(request) => boolean` callback for header and query checks. Native ordering and dependencies are preserved.
- **Server functions:** include their base path when they use Clerk's `auth()` helper; `/_serverFn` is Start's default. Private resources must still check authentication and ownership independently.

Selecting middleware does not set cache policy.

## Authenticate without Clerk middleware

With middleware, use Clerk's Start `auth()` helper. Without middleware, that helper throws:
authenticate through [`clerkClient().authenticateRequest(request)`](https://clerk.com/docs/reference/backend/authenticate-request),
handle handshake headers or redirects, then authorize using `.toAuth()`. Fetch a full user only after
verifying identity with `clerkClient().users.getUser(userId)`.

## Revalidate public responses

Call these helpers from an independently authorized server route, webhook or server function:

```ts
import { revalidateTag, revalidateUrl } from "kizlo/tanstack-start/cloudflare"

await revalidateTag("catalog")
await revalidateUrl("/collections")
await revalidateUrl(new URL("https://shop.example/product/shirt?size=m"))
```

The active Start execution context must provide native `cache.invalidate()`.
Both helpers mark matching responses stale; the next request refreshes them under their stored
stale-while-revalidate policy. They do not regenerate pages immediately. Missing support and provider failures throw.

URLs accept an absolute pathname or a same-origin HTTP(S) URL. Queries and fragments are ignored:
revalidating `/collections?page=1` selects every query variant of `/collections`, without selecting
`/collections/featured`. Cross-origin URLs and embedded credentials are rejected. Tags are scoped to the request host.

## Migrate and verify

Replace `kizlo/cloudflare` and `kizlo/cloudflare/vinext` imports with the Start-specific entry point.
Remove Vinext configuration and compatibility patches. Keep existing stored resources until their
retirement is authorized. Use `geoCloudflare()` only behind trusted ingress that prevents forged
`CF-Connecting-IP` headers; it validates syntax, not the sender.

Verify public MISS/HIT behavior on an isolated deployment, then test tag invalidation, private guards
and signed-in versus signed-out public HTML. A local build or dry-run does not prove edge caching,
account permissions or live Clerk behavior. No R2, Durable Objects or Worker response-cache implementation is installed.
