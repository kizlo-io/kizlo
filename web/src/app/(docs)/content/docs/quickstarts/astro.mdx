---
title: Astro
description: Use direct WordPress APIs from Astro pages and static browser code.
---

Complete [Installation](/docs/installation), then set `PUBLIC_KIZLO_WP_URL` to the WordPress origin.

```ts title="src/lib/kizlo/client.ts"
import { createBrowserClient } from "kizlo/browser"
import { introspection } from "./generated/introspection.browser"

export const client = createBrowserClient({ url: import.meta.env.PUBLIC_KIZLO_WP_URL!, endpoints: introspection })
```

## Render content

```astro title="src/pages/index.astro"
---
import { requireData } from "kizlo"
import { client } from "../lib/kizlo/client"
const posts = requireData(await client.kizlo.content.post.list({ query: { per_page: 10 } }))
---
<ul>{posts.map(post => <li>{post.title.rendered}</li>)}</ul>
```

Static output fetches this content at build time. Use Astro server output when you need request-time rendering. Interactive `<script>` code can import the same client and call WordPress directly; configure its exact origin in WordPress settings.

The repository's `templates/astro/src/pages/direct.astro` is prerendered HTML with a browser storefront. Its product, cart, and checkout calls need no Astro application server.

## Add SEO

Use `deserializeSeo` from `kizlo` for a non-null post `kizlo.seo` block. `resolvePageHead`, root-head, manifest, robots, and sitemap helpers remain in `kizlo/astro/server`. Pass the direct public client to helpers that fetch site data.
