---
title: TanStack Start (Solid)
description: Fetch WordPress from SSR and browser navigation with one direct client.
---

Complete [Installation](/docs/installation), then set `VITE_KIZLO_WP_URL` to the WordPress origin.

```ts title="src/lib/kizlo/client.ts"
import { createBrowserClient } from "kizlo/browser"
import { introspection } from "./generated/introspection.browser"

export const client = createBrowserClient({ url: import.meta.env.VITE_KIZLO_WP_URL!, endpoints: introspection })
```

## Load content directly

```tsx title="src/routes/index.tsx"
import { createFileRoute } from "@tanstack/solid-router"
import { requireData } from "kizlo"
import { client } from "@/lib/kizlo/client"

export const Route = createFileRoute("/")({
  loader: async () => requireData(await client.kizlo.content.post.list()),
})
```

The loader calls WordPress during SSR and browser navigation. No Kizlo proxy route or server function is needed for public content. Use native server functions for independent application work that requires your own private dependencies.

## Add metadata and hosting

`resolvePageHead` and `renderJsonLd` remain under `kizlo/tanstack-start`. Root-head, manifest, robots, and sitemap route helpers remain under `kizlo/tanstack-start/server`. Convert raw SEO with `deserializeSeo` from `kizlo`.

See [authentication](/docs/concepts/authentication) for user tokens and [Cloudflare](/docs/quickstarts/cloudflare) for optional Worker caching and revalidation.
