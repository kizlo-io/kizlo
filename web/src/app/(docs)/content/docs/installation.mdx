## Prepare WordPress

Install and activate the Kizlo plugin on your CMS. Activate companion plugins for WooCommerce or CF7 when you need those APIs.

<DownloadButton plugin="kizlo" />

Create an Application Password for an authorized WordPress service user under **Users → Profile**. Keep it private. In **System → Authentication**, allow your frontend's exact origin, even when external authentication is disabled.

## Install and generate

```bash
npm install kizlo
```

```ts title="kizlo.config.ts"
import { defineConfig } from "kizlo/config"

export default defineConfig({ dir: "src/lib/kizlo/generated" })
```

```bash title=".env"
KIZLO_WP_URL=https://cms.example.com
KIZLO_WP_USERNAME=service-user
KIZLO_WP_APP_PASSWORD=your-private-application-password
```

```bash
npx kizlo generate
```

The output contains `introspection.ts` for trusted service operations and `introspection.browser.ts` for explicitly exposed APIs. Commit both files. Add `kizlo check` to CI.

## Use the client

Follow your framework's quickstart: [Next.js](/docs/quickstarts/nextjs), [Astro](/docs/quickstarts/astro), [TanStack React](/docs/quickstarts/tanstack-start/react), or [TanStack Solid](/docs/quickstarts/tanstack-start/solid). A static frontend needs no Kizlo application backend.

For local WordPress, set `local: true` in your config and run `npx kizlo dev` with Docker running. The CLI manages local credentials; point your frontend's public CMS URL at the local WordPress URL it prints. See [CLI configuration](/docs/concepts/cli#configuration).

Upgrading an existing app? Read [Migrate to v1](/docs/concepts/migration-v1) before removing the old RPC server.
