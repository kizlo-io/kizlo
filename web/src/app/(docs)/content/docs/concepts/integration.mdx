WordPress plugins own API behavior, permissions, validation, and private data. Kizlo generates typed clients from the routes they publish.

## Add functionality

Register a final endpoint with [`kizlo_register_route`](/docs/php/functions/register-route). Declare its input, response, errors, access policy, and permission callback beside its implementation. Browser visibility is explicit; omitted access defaults to admin.

| Access | Intended caller |
| --- | --- |
| `public` | Anonymous visitors |
| `authenticated` | Verified customers, with resource ownership checked by the route |
| `session` | Signed cart sessions or the route's native session proof |
| `preview` | A resource-scoped preview token |
| `admin` | Authorized WordPress service users or administrators |

Regenerate the [introspection](/docs/concepts/introspection) after changing a route. Permission checks always run in WordPress, including for callers that bypass the SDK.

## Companion packages

WooCommerce and CF7 plugins expose the final storefront and submission APIs. Their TypeScript packages contain schemas and pure presentation utilities. Activate the companion plugin before generating its endpoints.

Auth providers supply signed user tokens. WordPress verifies them using the common [authentication configuration](/docs/concepts/authentication); a frontend integration server is unnecessary.

## Receive signed events

Optional application webhooks are independent of the API client:

```ts title="src/app/api/kizlo/webhooks/route.ts"
import { createWebhookHandler } from "kizlo/server"
import { nextRevalidation } from "kizlo/nextjs/server"

export const POST = createWebhookHandler({
  secret: process.env.KIZLO_WP_SECRET!,
  events: [{ ...nextRevalidation(), failureMode: "retry" }],
})
```

Configure the WordPress webhook backend URL to match your app's `/api/kizlo` prefix. The sender appends `/webhooks`. Required handlers return a failure for retry; optional failures are logged.

For existing procedure integrations, follow [the v1 migration guide](/docs/concepts/migration-v1).
