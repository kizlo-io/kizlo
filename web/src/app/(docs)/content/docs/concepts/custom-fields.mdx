Configure custom fields for a post type or taxonomy in the Kizlo WordPress settings, then run
`kizlo generate`. The generated WordPress contract uses the configured field names and value types instead
of a generic record.

## Read fields from public models

Read managed public content fields under `kizlo.custom`:

```ts
const { data: post, error } = await client.kizlo.content.post.retrieve({
  params: { identifier: "hello-world" },
})

if (error) throw error
post.kizlo?.custom.company_name // string when the configured field exists
```

Unlocked content with no configured fields returns `custom: {}`. Password-protected public content hides its private envelope as `kizlo: null`.

## Read and write through WordPress

Managed post-type and taxonomy write endpoints accept a grouped `custom` object. Fields that are required in
WordPress are required when creating content. Update requests may include only the fields that changed.

```ts
const response = await admin.kizlo.postTypes.post.create({
  body: {
    title: "Hello world",
    custom: {
      company_name: "Acme Ltd",
    },
  },
})

if (response.error) throw response.error

response.data.kizlo.custom.company_name // string
```

Raw response paths differ by API surface:

| Content | Raw response | Public Kizlo model |
| --- | --- | --- |
| Post types and taxonomies | `kizlo.custom` | `custom` |
| WooCommerce REST products | `kizlo.custom` | `custom` |
| WooCommerce Store API products | `extensions.kizlo.custom` | `custom` |

Custom field names may match standard fields such as `content`, `taxonomy`, or `kizlo` because the group keeps
them separate from the API's own properties.

## Migrate root-level fields

Custom fields previously appeared beside standard properties in requests and responses.

```ts title="Before"
await admin.kizlo.postTypes.post.create({
  body: {
    title: "Hello world",
    company_name: "Acme Ltd",
  },
})

response.data.company_name
post.company_name
```

Move every custom field into `custom`. Raw managed WordPress responses place the group inside `kizlo`, while
public Kizlo models expose it directly.

```ts title="After"
await admin.kizlo.postTypes.post.create({
  body: {
    title: "Hello world",
    custom: {
      company_name: "Acme Ltd",
    },
  },
})

response.data.kizlo.custom.company_name
post.kizlo?.custom.company_name
```

Regenerate `introspection.ts` after updating the Kizlo plugins or changing custom-field settings. See the
[introspection](/docs/concepts/introspection#generate-the-introspection) for generation and commit guidance.

File custom fields return the shared [`Media`](/docs/reference/types/media) union.
