== Changelog ==

= 0.9.0 =
* Added: Add kizlo/v1/taxonomies/:taxonomy REST routes that resolve a term by id or slug server-side, so headless clients can fetch a single term by slug in one request instead of a list-then-get round trip.
* Added: Include the resolved term URL in the category REST enrichment so the headless category API can expose it.
* Added: Post-type API responses now include the resolved public `url` (built from the Kizlo site-URL setting) and a full `featured_media` object with `width`, `height`, `mime`, responsive `variants`, and a ready-to-use `srcset` string (generated by WordPress' own resolver) via the shared media resolver.
* Changed: Settings responses no longer include the read-only publicly_queryable flag on post types and taxonomies, and every settings update endpoint now returns the saved section (previously some replied 204). Updating an unknown post type or taxonomy slug now returns a 400 instead of silently creating an orphan entry.
* Removed: Remove the configurable sitemap index pathname setting. The sitemap index is now fixed at /sitemaps/index.xml, matching where the frontend route is mounted, so robots.txt always advertises a path that resolves.
* Fixed: Fix collection filters being ignored on the post-type list route. The route passed the raw request to the posts controller without the controller's collection params, so WordPress never ran its sanitizers and filters that need transforming (slug, categories, tags, author, include/exclude) were silently dropped. The route now attaches and sanitizes those params before delegating, so list filtering works.

[See the full changelog](https://github.com/kizlo-io/kizlo/blob/main/plugins/kizlo/CHANGELOG.md).
